# Trailblazers meeting attendance

## Deploy and use

1. Run `supabase/migrations/202611030001_trailblazers_attendance.sql` once as
   **postgres** in the Supabase SQL Editor. Apply it after all existing migrations.
   Keep table RLS enabled.
2. Deploy the updated code to Vercel. No new environment variables or API keys
   are required. The existing Google Calendar API key must be able to read the
   public `vpresident.ufnsbe@gmail.com` calendar; this was verified locally.
3. As an admin or E-board member, open **Manage event check-in** and select
   **Trailblazers meetings**. Select an upcoming meeting, semester, optional zone,
   password and duration, then open check-in as usual.
4. Attendees use the existing `/sign-in` page and QR code. An open meeting appears
   in the selector alongside any other open chapter events. Duplicate prevention,
   UF-email matching, sign-in autofill, expiry and passwords work as before.

The main `/events` calendar continues using only the chapter calendar. The program
calendar is read only for event management. Both upcoming options and check-in
submission validation filter titles containing **Trailblazers**, case-insensitively.
Recurring meetings are expanded into individual occurrences. Sunday CEB meetings
are not offered. Google changes may take five minutes to appear. Only future or
currently running occurrences are offered for initial setup; configured meetings
can be reopened later from their source's configured list.

## Attendance-only policy

The database reserves category `trailblazers` for events from this program calendar
and forces it during setup. A trigger also enforces the category for direct event
writes. Titles from this source must contain Trailblazers. CEB titles are rejected.
Points are generated by the database: **Trailblazers always earns zero**. The category
cannot be assigned to events from a different calendar.

Trailblazers meetings are excluded from chapter attendance totals, active-member
GBM/event counts, leaderboard participation, and general-event bonus denominators.
Bonuses remain manual; do not include program meetings when awarding chapter
attendance bonuses. Trailblazers attendance alone does not create leaderboard
participation or establish a first recorded chapter-attendance date.

Members see **Trailblazers attendance** separately for the selected semester.
Admins see the same section on member detail pages and can add or remove missed
program attendance using the existing audited correction tools. E-board members
retain check-in management only and cannot correct member attendance or points.
No program roster restriction is introduced: anyone with the event password and a
UF email can check in, matching the existing anonymous attendance workflow.

The migration rebuilds only the generated `base_points` column to support zero
points; it does not delete attendance or member records. If matching events from
this program calendar already exist, they become attendance-only. If non-Trailblazers
events from that calendar already exist, the transaction aborts for review rather
than silently reclassifying them. Existing chapter event scores remain unchanged.

## Verification

`npm run test:calendar`, `npm run test:portal`, and `npm run test:reporting` cover
source filtering, chapter score exclusions, history and report behavior.
`tests/trailblazers.sql` runs against a disposable `trailblazers_test` database cloned
from the E-board fixture after applying this migration. Never run fixtures against
production. It checks E-board setup, rejection of CEB titles and wrong source
categories, forced zero points, check-in/reopen, duplicate prevention, and unchanged
chapter reporting aggregates.

After deployment, open a meeting and check in with a test UF member. Confirm it
appears only in Trailblazers attendance, with no change to chapter points, membership
progress or leaderboard rank. Close/reopen the meeting and verify duplicate check-in
still creates only one attendance row.
